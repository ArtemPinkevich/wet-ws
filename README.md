# WET-WS

Визуальный WebSocket-трансивер на Node.js и TypeScript. Подключите клиент и сервер через WET-WS, наблюдайте обмен сообщениями, управляйте пересылкой и отправляйте собственный текст через браузер или настольное приложение.

## Возможности

- Независимое подключение клиента и сервера в любом порядке.
- Автоматическая пересылка текстовых сообщений с общим переключателем обоих направлений.
- Ручная отправка текста клиенту или серверу, в том числе при выключенной автопересылке.
- Общая история сообщений, статусы и очистка истории без разрыва соединений.
- Синхронизация нескольких вкладок и восстановление связи интерфейса с сервисом.
- Запуск из исходников, настольная сборка Windows и серверная поставка Docker.

## Быстрый старт

Требуются Node.js 24.21.0 и npm. Из корня проекта:

```bash
cd app
npm ci
npm run build
npm start
```

Откройте [http://localhost:8080](http://localhost:8080).

## Использование

1. Укажите WebSocket-адрес целевого сервера и подключитесь к нему.
2. Настройте адрес и порт приёма клиента и запустите приём.
3. Подключите ваш WebSocket-клиент к адресу WET-WS.
4. Наблюдайте обмен в истории. При необходимости выключите автоматическую пересылку или отправьте собственный текст выбранной стороне.

Порядок подключения сторон можно менять. Для локальной проверки доступен [клиент и эхо-сервер](app/README.md#ручной-эхо-стенд).

## Windows и Docker

Windows ZIP создаётся командой `npm run make` из каталога `app`. Распакуйте готовый архив целиком и запустите `wet-ws-ai.exe`; отдельный Node.js для этой сборки не нужен.

Офлайн-поставка Docker создаётся командой `npm run make:docker`. Готовый комплект содержит `image.tar` и `compose.yaml`. Из его каталога:

```bash
docker load --input image.tar
docker compose up -d --pull never
```

Интерфейс доступен на порту 8080, приём внешнего клиента по умолчанию — на порту 8081. Для остановки выполните `docker compose down`.

Требования к сборке и расположение результатов описаны в [README приложения](app/README.md#результаты-сборки-и-очистка).

## Ограничения

- Один экземпляр сервиса работает с одной парой клиент–сервер.
- История хранится в памяти и теряется после остановки сервиса.
- Сообщения, полученные без готового адресата или при выключенной пересылке, не досылаются автоматически.
- Поддерживаются текстовые сообщения; бинарные сообщения не поддерживаются.
- Статус отправки не подтверждает обработку сообщения приложением-получателем.
- Поддержанные варианты поставки — Windows x64 и Docker Linux/amd64. Публичное размещение в интернете и корпоративная эксплуатация отдельно не проверены.
