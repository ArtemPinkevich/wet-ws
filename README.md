# WET-WS

Визуальный WebSocket-трансивер для наблюдения обмена между клиентом и сервером. Подключите обе стороны через посредник и просматривайте сообщения в общем чате через браузер или настольное приложение.

Проект находится в разработке. Текущий объём — наблюдение, управляемая автоматическая пересылка и ручная отправка текстовых сообщений. Iteration 3 принята автором 2026-10-18; досылка ранее принятых сообщений пока не реализована.

## Возможности

- Независимый запуск приёма клиента и подключения к серверу, в выбранном пользователем порядке.
- Пересылка новых текстовых сообщений, когда получатель подключён; общий переключатель обоих направлений.
- Собственный текст клиенту или серверу, в том числе при выключенной автопересылке и во время живого обмена.
- История обоих направлений, статусы и очистка истории без остановки соединений.
- Общий сеанс сервиса в нескольких синхронизированных вкладках.
- Автоматическое восстановление связи интерфейса с сервисом.
- Работа в локальной сети; Windows-приложение и серверная поставка Docker.

## Быстрый старт

### Windows x64

Если у вас есть готовый Windows ZIP, распакуйте его целиком и запустите `wet-ws-ai.exe`. Отдельный Node.js или браузер для настольной программы не нужен.

### Docker: офлайн-поставка Linux/amd64

На компьютере должен быть установлен Docker с Linux-контейнерами и Docker Compose v2. Скопируйте весь каталог офлайн-поставки: `image.tar`, `compose.yaml`, `README.txt` и `SHA256SUMS`.

Из каталога поставки:

```bash
docker load --input image.tar
docker compose up -d --pull never
```

Откройте http://localhost:8080. Для другого компьютера локальной сети используйте адрес Docker-хоста. По умолчанию приём внешнего клиента — на порту 8081; порты 8080 и 8081 должны быть свободны и доступны через firewall. Интернет для этого запуска не требуется.

Остановка:

```bash
docker compose down
```

Готовые поставки в рабочей копии создаются в `app/out/releases/`. Команды их сборки — в [README приложения](app/README.md#результаты-сборки-и-очистка). Этот локальный каталог не входит в исходники репозитория.

### Запуск из исходников

Требуются Node.js 24.21.0 и npm. Из корня репозитория:

```bash
cd app
npm ci
npm run build
npm start
```

Откройте http://localhost:8080. Подробности — в [сборке и запуске](app/README.md#сборка-и-запуск).

## Проверить обмен

В проекте есть минимальный [клиент и эхо-сервер](app/README.md#ручной-эхо-стенд), запускаемые отдельно от трансивера.

1. Запустите эхо-стенд и трансивер.
2. Подключите трансивер к эхо-серверу и включите приём клиента.
3. Подключите проверочный клиент к трансиверу и отправьте текст.
4. Клиент получит тот же текст обратно, а чат трансивера покажет оба направления.

Адреса для локального, Docker- и LAN-запуска приведены в инструкции стенда.

## Статус и ограничения

- Iteration 3 завершена и принята автором 2026-10-18 после живого демо. Решения и результаты — в [Context Pack 03](docs/engineering/iterations/iteration-03/context-pack.md). Новые ZIP/Docker-поставки в этой итерации не собирались.
- Один экземпляр сервиса обслуживает одну пару клиент–сервер. История хранится в памяти и теряется при остановке сервиса.
- Сообщения, принятые без готового получателя, видны в истории, но автоматически позднее не досылаются.
- Поддерживается текстовый обмен; binary-сообщения не поддерживаются. Запись в истории не доказывает обработку сообщения приложением-получателем.
- Проверены Windows x64 и Linux/amd64-контейнер в Docker Desktop на Windows. ARM, macOS, отдельный Linux-хост и второй физический компьютер LAN отдельно не проверены.
- Публичное размещение сервиса в интернете и корпоративная эксплуатация не входят в проверенный объём.
