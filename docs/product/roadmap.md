# Дорожная карта продукта

Карта определяет порядок итераций, их цели и состав по [user-stories.md](user-stories.md). Содержание историй хранится только в backlog. Каждая включённая история выполняется целиком в одной итерации. Требования, критерии приёмки, инженерные уточнения и результаты гейтов относятся к материалам конкретной итерации / Iteration Context Pack. Календарные сроки карта не задаёт.

## Итерация 1 — проверка вариантов поставки

**Статус:** завершена.

**Цель:** проверить общую основу серверной и настольной поставок до разработки функций трансивера.

**Истории:** не назначены; итерация проверяет техническую основу поставок. Истории поставки остаются в разделе «Позже».

**Почему здесь:** общая основа нужна для последующих функций в обеих поставках.

**Результат:** подтверждена общая техническая основа браузерной и настольной поставок. Итог и ограничения — в [Context Pack](../engineering/iterations/iteration-01/context-pack.md).

## Итерация 4 — повторные проверки и UI-редизайн

**Статус:** 2026-10-24 — доработанная чат-ревизия OpenDesign согласована автором для реализации; Implementation Ready PASS получен до production-кода. Рабочий интерфейс перенесён в настоящее приложение: библиотека слева, редактор в центре, чат справа, изменяемые ширины и сворачивание редактора. US-011–013 реализованы; полный check, 30 тестов, реальный UI/WS в Edge и Electron и независимый повторный review — PASS. Приёмка владельцем работающего приложения ещё не зафиксирована; Iteration Done ожидает её. Конкретная ревизия, доказательства и ограничения — в [Context Pack 04](../engineering/iterations/iteration-04/context-pack.md). Будущий выбор представления трафика — [PB-002](backlog.md#pb-002--переключение-представления-трафика), вне scope. localStorage — максимум 20; desktop persistence временно не гарантируется (TB-002). Новые ZIP/Docker не собирались. Автор разрешил открыть Pull Request; публикация реализации идёт отдельно от прежних изменений инструкций процесса.

**Цель:** сделать подготовленные сообщения пригодными для повторного использования.

**Истории:**

- [US-011](user-stories.md#us-011--редактирование-полученного-сообщения).
- [US-012](user-stories.md#us-012--повторная-отправка).
- [US-013](user-stories.md#us-013--сохранение-сообщений).

**Почему здесь:** опирается на отправку сообщений из итерации 3.

**Результат:** пользователь может повторять проверки и повторно использовать сохранённые сообщения.
