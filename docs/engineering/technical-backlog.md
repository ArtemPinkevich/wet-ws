# Technical Backlog

Canonical реестр сознательно отложенных технических вопросов. Будущая пользовательская ценность относится к [Product Backlog](../product/backlog.md). Здесь достаточно контекста, принятого допущения, последствия и конкретного условия возврата; детальная спецификация не нужна.

Статусы: `ACCEPTED_DEFERRED` — последствия временно приняты автором, не blocker исходной итерации; `REVIEW` — наступил trigger или прямое пересечение со scope; `RESOLVED` — есть ссылка на принятое и проверенное решение. Записи получают ID `TB-NNN`.

## TB-001 — Асимметричная скорость соединений

- **Status:** `ACCEPTED_DEFERRED`, решение автора 2026-10-11; не блокирует Iteration 2. Trigger US-008–US-010 рассмотрен в Iteration 3 (2026-10-18): planning REVIEW → scope review выполнен, отдельная flow-control реализация не требуется для одиночных ручных отправок. Сохраняется исходное принятое допущение; это не подтверждение устойчивости.
- **Context / problem:** входящий поток может быть быстрее исходящего; данные, ожидающие пересылки, потенциально накапливаются в памяти.
- **Why deferred:** Iteration 2 реализует обычное наблюдение и пересылку; собственная flow-control механика сейчас усложняет scope. Не определять и не реализовывать queue/message size limits, backpressure, throttling, dropping policy или overflow handling.
- **Current accepted assumption:** пересылка работает без специальной политики ограничения очереди; эксплуатационные последствия временно приняты. Это заменяет ранее обсуждённые 1 МиБ / 100 сообщений и отбрасывание при переполнении. Не обещает неограниченную память или отсутствие технических пределов библиотеки. Бюджет истории — отдельное принятое решение, не очередь отправки.
- **Risk / consequence:** при медленном получателе возможны рост памяти и задержки, исчерпание ресурсов и прекращение работы; устойчивость под нагрузкой пока не подтверждена.
- **Review trigger:** пересмотр после US-004/US-008–US-010 выполнен в [Context Pack 03](iterations/iteration-03/context-pack.md). Следующий возврат — до добавления пакетной/автоматизированной повторной отправки либо при scope с throughput, нагрузкой, очередями, latency или устойчивостью; также при выявленной тестами или использованием проблеме. Одиночная ручная отправка использует тот же SendTarget без очереди приложения. Нагрузочная проверка остаётся NOT RUN.
- **Origin iteration:** [Iteration 2 Context Pack](iterations/iteration-02/context-pack.md), обсуждение упрощения пересылки и явное решение автора об откладывании concern. Решение и условия возврата хранятся здесь; Context Pack содержит только ссылку и статус.

## TB-002 — Сохранность localStorage при перезапуске Electron

- **Status:** ACCEPTED_DEFERRED — прямое решение автора в голосовом обсуждении 2026-10-19: сейчас допустимо, что заготовки desktop пропадают после запуска; стабильность хранения не прорабатывать.
- **Context / problem:** Electron открывает HTTP UI со свободным портом, иногда LAN host; localStorage привязан к origin, поэтому новый запуск может не видеть прежний набор.
- **Why deferred:** автор выбрал минимальный localStorage/20 и явно снял требование гарантии сохранности desktop между запусками.
- **Current accepted assumption:** используется существующий Electron runtime/browser storage; стабильный origin, перенос и восстановление между origin сейчас не реализуются.
- **Risk / consequence:** desktop может показать пустой список; данные другого origin недоступны из текущего UI. Это не гарантия фактического удаления и не проверенная сохранность.
- **Review trigger:** включение гарантированной desktop persistence либо работа над US-019–021/переносимостью, когда согласуются сохранность и пределы импорта/экспорта. Сам выбор будущего импорта сейчас trigger не активирует.
- **Origin iteration:** [Iteration 04](iterations/iteration-04/context-pack.md), голосовое решение автора; допущение не блокирует текущий scope.
