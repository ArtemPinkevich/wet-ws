## Цель, scope и основания

Единственная выбранная история — [US-025](../../../product/user-stories.md#us-025--индикация-некорректного-json-при-редактировании): сразу замечать некорректный JSON при редактировании сообщения в рабочей области. Автор прямо запросил новую историю, только её в следующую итерацию и 3–5 вариантов индикации для UI-согласования (сообщение в чате 2026-10-26).

Подтверждено: потребность автора в ненавязчивой обратной связи во время редактирования. Вывод: текущее отсутствие такой индикации мешает обнаруживать ошибку до дальнейших действий. Частота проблемы, влияние на других пользователей и готовность платить не проверены; интервью и внешние пользовательские тесты недоступны.

US-015 шире: включает форматированное представление и анализ JSON. US-025 выделяет только live-индикацию; US-015 целиком не выбрана и не объявляется выполненной. Остальные истории, форматирование/исправление текста, JSON Schema, валидация бизнес-содержимого, редизайн рабочего стола, новые протоколы и поставки вне scope.

Источники: [roadmap](../../../product/roadmap.md), [результат 05](../iteration-05/context-pack.md), [canonical architecture](../../architecture/overview.md), текущие `app/src/frontend/message-ui/message-ui.ts`, `app/src/frontend/app-shell/index.html` и `app/src/frontend/ui.ts`. Исходный Git HEAD: `b8e5e23f7f243b18a9ff6617fee0573b1d757dd3`; рабочее дерево до подготовки чистое.

## Поведение и критерии — проект для согласования

| ID | Наблюдаемое поведение / критерий | Проверка |
|---|---|---|
| AC-01 | При работе в контексте JSON некорректный синтаксис виден во время редактирования, без отправки, blur или отдельной команды проверки | Ввести/вставить ошибочный JSON, исправить, undo/redo; проверить соответствие индикатора текущему тексту |
| AC-02 | Индикация ненавязчива: без модального окна, toast на каждый ввод, перехвата фокуса и изменения текста/выделения/прокрутки | Непрерывный ввод, клавиатура, прокрутка, исправление; интерактивное сравнение вариантов |
| AC-03 | Корректный JSON снимает индикацию ошибки; загрузка сообщения/заготовки и новый черновик не сохраняют чужое состояние | Валидный → невалидный → валидный, смена источника/очистка |
| AC-04 | Обычный текст и пустой черновик не получают ложного предупреждения JSON | Согласовать явный режим или правила определения JSON; проверить неоднозначные значения |
| AC-05 | Проверяется синтаксис JSON, включая корневые примитивы; схемы, бизнес-содержимое и автоисправление не добавляются | Объект, массив, строка, число, boolean, null; trailing comma, незакрытые скобки/строки |
| AC-06 | Информационный статус не меняет payload, dirty, адресата и доступность действий по прежним условиям | CR/CRLF, literal-текст, копия/сохранение, реальная отправка некорректного JSON при готовом адресате |
| AC-07 | Ошибка различима не только цветом; статус доступен с клавиатуры и не озвучивается назойливо на каждом символе; narrow сохраняет место для текста | Проверка интерактивного прототипа и реализации: wide/narrow, focus, доступное название/описание |
| AC-08 | Проверка не подменяет новый результат устаревшим и не запускается из-за каждого события трафика | Быстрая серия правок/загрузка нового текста, длинное сообщение при живом обмене; задержку и метод проверки уточнить до Ready |

AC находятся в статусе proposal, кроме прямых требований автора (AC-01/02 и 3–5 UI-вариантов). Конкретный способ отличать JSON от обычного текста, задержка проверки, пустое содержимое в явно выбранном JSON-режиме и представление деталей ошибки требуют решения до Ready. Нельзя молча ограничить JSON только объектами/массивами или автоматически выключить проверку после первого ошибочного символа.

Предложенные альтернативы (не выбранный дизайн):

1. **Статус в нижней строке:** компактные значок и «Некорректный JSON», подробность по запросу. Минимум визуального вмешательства, но статус дальше от места ошибки.
2. **Метка у заголовка редактора:** нейтральная компактная `JSON !` с текстом/доступным описанием; подробность по клику/клавиатуре. Заметна без окрашивания поля.
3. **Тонкий акцент границы:** мягкая янтарная полоса у редактора плюс короткая подпись ошибки. Состояние видно периферийно, текстовое обозначение обязательно.
4. **Локальный маркер:** значок в gutter у строки синтаксической ошибки и компактный общий статус. Точнее указывает место, но требует достоверного определения позиции и fallback при её отсутствии.

Все варианты должны переключаться в одном интерактивном прототипе с одинаковыми данными; показаны valid/invalid/empty/plain-text, ввод/исправление, wide/narrow. Общий вопрос определения JSON показать явно (предложение: Text/JSON), не смешивать его с выбором визуального индикатора. Фикстуры/transport — симуляция. Согласование варианта отдельно от технической готовности и приёмки реализации.

Временные экспорты при необходимости — только локально в `iteration-06/mockups/`, уже исключены корневым gitignore. Перед выбором сохранить идентифицируемую ревизию либо точный runnable export; один mutable link недостаточен. Canonical UI остаётся evidence реализации 05.

### Исправление по Independent Reviewer

Первый проход обнаружил blocker: regex мог принять слова `position 3` / `line 2 column 1` из процитированного payload в диагностике JSON.parse за достоверную позицию. Добавлены unit- и интерактивный regression (в частности `line 2 column 1\nxx` не создаёт маркер строки, подробности честно сообщают отсутствие позиции).
