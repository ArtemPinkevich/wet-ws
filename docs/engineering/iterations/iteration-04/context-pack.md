Нужные browser modules добавляются в существующий runtime allowlist.

- Выбор карточки подсвечивает её; отдельное действие открытия загружает literal копию в редактор. Dirty dialog отменяется без потери target/text/selection. Новые события и статусы не пересоздают editor DOM.
- Прямая повторная отправка карточки использует исходное направление (server → client, client → server, user → сохранённый target); editor/library используют видимый выбранный адресат. Каждое действие вызывает прежний send, без автоматического retry. Сохранение не требует control sync.
- Library: максимум 20, пустой набор при первом запуске, без demo seeds; read/write errors, повреждение и quota не маскируются успехом. Политика конкуренции вкладок — прежнее ограниченное last-write-wins предложение; durable cross-tab merge не обещается. TB-002 desktop origin/persistence остаётся принятой отсрочкой. Импорт/экспорт/удаление/лицензии не добавлять.
- Clear означает весь текущий синхронизированный набор отрисованных history ID на момент действия (не только viewport), новые события не захватываются последующим await; редактор/библиотека не очищаются.
- Потеря полного payload в backend history — существенное исключение безопасности: добавить явный optional `payloadUnavailable:true` у History.Entry, когда history сохранила заглушку. Guard валидирует флаг; UI показывает notice, блокирует copy/repeat такого источника. Нельзя распознавать утрату по строковому шаблону. Это минимальная protocol delta для достоверной доступности, без нового API извлечения исходника.
- Визуально близкий syntax/pretty preview используется только при чтении; редактор, quick-send, сохранение и повтор берут исходный literal text. Preview не подтверждает JSON-корректность или доставку. Состояния отправки/ошибки остаются доступны в карточке/описании, даже если в прототипе footer скрыт.

**Минимальные ограничения для будущих прототипов — сверено по backend/контракту, не результат проверки нового UI:**

- Одна пара client/server, независимый порядок подключений; listener и подключённый клиент различаются. Отключение клиента оставляет listener; остановка приёма закрывает клиента, сохраняя сервер. Ошибка/закрытие одной стороны обычно не закрывает вторую; binary закрывает обе стороны, listener остаётся. UI control connection имеет отдельное состояние синхронизации.
- Server URL сейчас только `ws://`, без credentials/hash; общий subprotocol меняется после отключения server и listener. Поля/состояния подключения должны сохранять эту семантику, хотя их композиция свободна.
- `autoForward` — один общий переключатель двух направлений. OFF продолжает наблюдение и не создаёт очередь/автодосылку. `send {target,text}` работает независимо от OFF, требует готового адресата и актуального backend-состояния. Ручная отправка создаёт новую запись; её результат не ACK приложения-получателя. Неизвестный исход не повторяется автоматически.
- В истории видимы источник client/server, ручной источник user с target, служебные event, время, ID/session, status/reason. Получено от стороны и передано на отправку — разные факты; направление нельзя обозначать только цветом. Backend не сопоставляет запросы и ответы и не сообщает причинные связи между сообщениями.
- History хранится в памяти, бюджет по умолчанию 1000 записей / 4 МиБ сериализованных записей. Старые записи вытесняются; чрезмерно большая запись получает текст-заглушку вместо payload. Отдельного признака утраты payload в Entry нет: достоверно отличить заглушку от такого же literal текста только по строке невозможно. Нельзя обещать получение полного исходника из backend; трактовка такого случая для edit/replay требует отдельного решения до Ready.
- Clear удаляет переданные UI идентификаторы `shown`, не разрывает соединения и не очищает локальные заготовки. Новые записи, пришедшие после снимка shown, сохраняются. При новой композиции/фильтрации нужно явно определить охват очистки до Ready.
- Изменение — копия исходного текста, не изменение истории. Выбор не отправляет; dirty replacement требует подтверждения с сохранением text/target/selection при отмене. Live/clear/eviction/reconnect не подменяют черновик; выбранное содержимое нужно удерживать для чтения при новых записях.
- Заготовки — localStorage профиля/origin, максимум 20; quota может наступить раньше. Save/load доступны без backend, send — нет. Никакого удаления/сортировки/импорта/экспорта; ошибка записи не успех, повреждение не сбрасывается молча. Desktop persistence исключение TB-002 сохраняется. Межвкладочная семантика конкурентной записи из старого инженерного предложения ещё не принята как реализация.

Источники проверки: `app/src/backend/application/application.ts`, `application.protocol.ts`, `connection/connection.ts`, `connection.protocol.ts`, `message-flow/forward.ts`, `message-flow.protocol.ts`, `history/history.ts`, `history.protocol.ts`, root `protocol.ts`; canonical overview, stories и AC-1–10 выше. Новый frontend stack и архитектурная delta не выбирались. Общий вывод: текущий send подходит для копирования/правки/повтора; завершённая техническая реализуемость конкретной композиции пока не доказана.

## Цель и текущие решения автора

Редактировать полученный текст, повторять отправку и сохранять именованные заготовки. Целиком выбраны [US-011](../../../product/user-stories.md#us-011--редактирование-полученного-сообщения), [US-012](../../../product/user-stories.md#us-012--повторная-отправка), [US-013](../../../product/user-stories.md#us-013--сохранение-сообщений) из [roadmap](../../../product/roadmap.md). Итерации 01–03 завершены, Iteration 03 принята 2026-10-18. Основание — истории и решения автора, не внешние пользовательские тесты или подтверждённый спрос.

**Действующее решение хранения, голосовое обсуждение 2026-10-19:** до **20 именованных заготовок в localStorage**, в браузере и Electron. Набор принадлежит профилю и origin интерфейса, не общему backend. Более ранний ответ «общую» и промежуточная идея пустого списка при новом посещении заменены этим последним решением. LocalStorage сохраняет данные между посещениями того же origin, пока browser/profile data доступны; требование очищать библиотеку при уходе не применяется. Между профилями/устройствами/server UI заготовки не синхронизируются.

**Явное исключение автора для desktop:** «не надо заморачиваться», если после запуска заготовки пропадают, это сейчас допустимо. У существующего Electron runtime меняются HTTP-порт и иногда host; стабильный origin/миграцию не реализуем в этой итерации. Это исключение гарантии межзапусковой сохранности US-013 для desktop, а не доказательство сохранности. Concern — [TB-002](../../technical-backlog.md#tb-002--сохранность-localstorage-при-перезапуске-electron), ACCEPTED_DEFERRED по прямому решению автора.

Вне scope: пакетная/автоматическая отправка, JSON tooling, новые поставки, серверное хранилище заготовок, backend template API, Docker data volume, стабильный desktop origin/миграция, лицензирование. Импорт/экспорт уже представлены US-019–021, отложены до будущего выбора roadmap; дублирующих историй не создаём. Расширенный набор ориентировочно до 200 — будущий [PB-001](../../../product/backlog.md#pb-001--расширенный-набор-заготовок), CANDIDATE; текущий лимит остаётся 20, лицензирование сейчас не реализуется. ## Историческое инженерное предложение — frontend localStorage

Это нереализованное предложение прежней компоновки: распределение frontend-ответственности пересматривается по новому прототипу; выбранные localStorage, лимит и функциональная семантика сохраняются. Оно не разрешает реализацию нового frontend.

Прежняя DELTA внутри общего UI: небольшая frontend-ответственность локального набора (например frontend/templates) владеет форматом, лимитом 20, чтением/записью и ошибками. Браузерный adapter изолирует localStorage для проверок, без будущей инфраструктуры и серверного storage-порта. App Shell создаёт/связывает эту ответственность с Message UI. App Model остаётся моделью backend-состояния и отправки, не объявляет локальный набор глобальным backend snapshot.

Message UI владеет черновиком/text/target/name/источником и заменой dirty; Chat UI передаёт выбор, затем получает выбранный ID для обводки. Вкладка рабочей области (редактор/сохранённые), активная narrow-область и раскрытие подключений локальны App Shell; переход не уничтожает редактор. History и Message Flow не меняют ответственности.

Предложенный browser формат: один versioned JSON-набор под собственным ключом localStorage, записи {id,name,text}, максимум 20. Отсутствие ключа — пустой набор; неизвестная версия/невалидные данные — явно недоступный набор, без автоматической перезаписи. Проверять unknown, уникальность ID, строки и число записей. Приложение управляет только своим ключом, не очищает чужой localStorage. ID генерируется через существующий getRandomValues-подход; имена не являются ключами, совпадение имён не перезаписывает запись.

Перед сохранением перечитывается актуальный набор, проверяются данные и число записей, создаётся новый набор и выполняется setItem; UI принимает его после успеха. При quota/запрете прежнее подтверждённое содержимое не заменяется пустым, черновик не стирается. У localStorage есть ограничения объёма и доступности; количество 20 не гарантирует вместимость 20 произвольно больших payload. Произвольный дополнительный байтовый лимит не назначен.

Вкладки того же origin/профиля используют browser storage events для перечитывания набора, не для подмены редактора. LocalStorage не предоставляет транзакционное read-modify-write между вкладками: для одновременных записей инженерное предложение — последняя записанная версия набора имеет приоритет; не обещаем collaborative merge/отсутствие потери конкурентного добавления. Каждый записываемый набор всё равно валидируется как максимум 20. Это явно описанная семантика простого локального набора, NOT ACCEPTED / NOT VERIFIED как реализация. Между независимыми браузерами синхронизации нет. Очистка browser data удаляет библиотеку; очистка истории WET-WS её не трогает.

Electron использует существующую persistent browser session/localStorage; никаких IPC/Node API в renderer и новых постоянных файлов приложения не вводится. При смене origin набор может не находиться после запуска: автор временно принял это, runtime не меняем ради стабильности. Docker/backend не сохраняют пользовательские заготовки. Экспорт/импорт может дать переносимость позже, но не восстанавливает автоматически уже недоступные данные и сейчас не реализуется.

Проверенные первичные источники, 2026-10-19: [WHATWG Web Storage](https://html.spec.whatwg.org/multipage/webstorage.html), [Electron Session](https://www.electronjs.org/docs/latest/api/session). Спецификация подтверждает origin scope, ошибки записи, persistence и отсутствие гарантированного locking между agent clusters; Electron документирует DOMStorage. Это возможности API, не результаты проверки приложения.

## Protocol & Data Contract

Backend contract impact NO_CHANGE / SKIP. Существующий [Message Flow protocol](../../../../app/src/backend/message-flow/message-flow.protocol.ts) send {target,text} покрывает повтор/изменённый текст. Нет save-template command, shared templates snapshot, server guards или дополнительного outcome в ControlResult. Текущие send-result/status, unknown outcome и reconnect без replay сохраняются.

Локальный versioned формат принадлежит frontend storage owner, валидируется при чтении/записи, не добавляется в root control protocol. Новые сетевые команды/смешанные версии не проектируются. Ошибка quota локальна и не изображается transport error. Локальная запись не требует актуального backend instance.

## Историческая UX delta — Concept A, не baseline редизайна

**Основа выбрана автором 2026-10-19:** [Concept A, чат справа / workspace слева](../iteration-03/mockups/main/concept-a-chat.png). Две предыдущие вертикальные композиции Iteration 04 отклонены. Новый вариант переносит структуру и светлую палитру A, добавляя подключения, полноценное редактирование/отправку и локальные заготовки.

Основное окно — **1920×1080, 16:9**. Верхняя строка: WET-WS, статусы клиента/сервера, «Подключения» и подтверждённая общая автопересылка. Под ней раскрываемая inline-полоса из двух групп: целевой сервер (URL, общий подпротокол, подключить/отключить) и приём клиента (адрес, порт, адрес для клиента, отключить клиента, начать/остановить приём). На главном макете полоса раскрыта, чтобы параметры были видны. При сворачивании освобождённая высота достаётся обеим рабочим колонкам; подключённость и forwarding остаются видимыми. До подключения полоса раскрыта, waiting/listening/connected различимы. Нового setup-экрана нет.

Ниже — две соседние высокие области, **рабочая область слева (~55%), чат/трафик справа (~45%)**. Ни редактор под чатом, ни третий постоянный sidebar подключений не входят в это предложение. Подключения функционально прежние, теперь собраны над обеими областями.

Слева — «Рабочая область» с двумя заметными вкладками **«Редактор» и «Сохранённые пакеты · N / 20»**. Маленький выпадающий список заменён реальным списком во второй вкладке. Это переключение содержимого только левой области; чат справа остаётся видимым. В режиме редактора показаны источник/ID, изменённый черновик и большое многострочное поле со своим scroll/номерами строк. Под ним — адресат, отправка, имя/сохранение новой заготовки и статус. Показанный JSON — вручную подготовленные sample data; JSON tooling/поиск/импорт в scope не добавляются. Исходная запись не редактируется; send создаёт новую side:user/target запись.

Вкладка «Сохранённые пакеты» показывает список именованных строк с коротким различимым ID и небольшим preview текста. На макете открыта эта вкладка с четырьмя illustrative записями и счётчиком 4/20. Клик по строке либо маленькая стрелка справа загружает копию в редактор и активирует вкладку «Редактор» после проверки dirty draft. Сам переход между вкладками не меняет текст, имя, адресата или выбранную запись и не требует подтверждения замены; подтверждение нужно только для загрузки другого содержимого. Позиция чтения списка сохраняется. До 20 строк прокручиваются внутри левой области, не удлиняя окно. При пустом наборе видны счётчик 0/20 и подсказка сохранить пакет из редактора. В состоянии 20/20 существующий список доступен, новое сохранение не вытесняет его строки. Удаление/порядок/импорт/экспорт не добавлены.

Справа: Client/Server обозначены колонками, сообщения с небольшим боковым смещением, компактными ID/временем и читаемым preview. Цвет стороны отделён от ручного происхождения: ручной пакет имеет небольшую amber-метку. Выбранная запись обведена тонкой синей рамкой. У карточки маленькая иконка 28×28 с tooltip/доступным именем «Загрузить копию текста в редактор»; больших кнопок «В редактор» нет. Карточка также выбирается обычным кликом/клавиатурой; выделение текста мышью не должно вызывать загрузку. Обе точки входа используют одно действие и одно подтверждение dirty draft.

Выбор переводит копию полного текста в левую рабочую область, а не отправляет её. При отказе заменить dirty draft прежние выбор и текст остаются; pending-выбор не перезаписывается новыми сообщениями. После clear/eviction уже загруженная копия остаётся, источник может обозначаться как удалённый из истории. Новые события не подменяют выбранное сообщение и положение чтения редактора. Независимые scroll редактора и трафика; UI не обещает установленные пары запрос–ответ или обработку получателем.
