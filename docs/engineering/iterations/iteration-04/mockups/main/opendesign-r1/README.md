## Открытие в OpenDesign

Выберите `index.html` в файлах текущего проекта и откройте его в Preview. Стартовая страница содержит прямые входы; ту же навигацию можно использовать в шапке каждой концепции. Каждую страницу можно открыть в Preview непосредственно:

| Файл | Концепция | Основная композиция |
| --- | --- | --- |
| `index.html` | Переключатель R1 | Прямые входы в четыре самостоятельные страницы |
| `registry.html` | Реестр | Плотная хронология метаданных, отдельные raw inspector и черновик |
| `trace.html` | Трасса | Общая временная шкала между фиксированными Клиент / WET-WS / Сервер; справа инспекция или отдельный черновик |
| `document.html` | Документ | Непрерывный журнал literal payload-блоков; выбранный блок и отдельная поверхность правки справа |
| `focus.html` | Фокус | Свободные режимы Наблюдать / Исследовать / Подготовить с сохранением состояния |

Все пути относительны корню этого проекта. Исходники: `app.js`, `styles.css`, пять HTML-файлов. Сборка и подключение к backend не нужны. Нужен Preview с JavaScript и обычными browser storage API. Для общей сессии переходите по внутренним ссылкам в одном Preview с тем же origin. Отдельные браузерные вкладки не являются синхронизированными backend-клиентами.

## Что реализовано

- Общие fixtures: короткие сообщения с обеих сторон, ручная запись с неизвестным исходом, system events, вложенный JSON более 200 строк, minified JSON с длинной строкой, literal HTML/Unicode, пустая строка. JSON не форматируется и не анализируется; tree/diff/validate не добавлены.
- Listener, client, server и control sync показаны раздельно. Server независим от listener/client; stop listener закрывает client, disconnect client оставляет listener. Настройки: ws:// URL, host/port listener и общий subprotocol.
- Автопересылка — один bool для обоих направлений. OFF не останавливает наблюдение, не создаёт очередь и не досылает старые записи. Ручная отправка требует sync и ready выбранного target, включая отправку пустой строки. При неизвестном исходе нет автоматического повтора.
- Выбор записи сохраняет доступный literal текст. Копирование в черновик не отправляет, не меняет target и не мутирует историю. Ручная отправка создаёт новую запись со статусом «Передано на отправку» без обещания обработки получателем.
- Dirty replacement подтверждается. Отмена сохраняет текст, target и диапазон выделения. Переключения страниц/режимов, live, clear, eviction и reconnect не заменяют черновик. Для вышедшей из истории выбранной записи явно обозначена локальная открытая копия.
- Автоматический demo-поток включён по умолчанию, интервал 4 секунды. Он не переводит пользователя к последним событиям. Возврат выполняется кнопкой «К новым сообщениям». Запуск/пауза потока находится только в отдельном demo toolbar.
- Clear удаляет только IDs, показанные на момент действия. Подключения и заготовки сохраняются. Симуляция ограничивает историю 1000 записями / 4 MiB, вытесняя старые; payload свыше 512 KiB заменяется текстовой заглушкой. Порог 512 KiB — выбранная константа этой симуляции, не утверждение о backend. Оригинал не восстанавливается, надёжный truncation flag не придуман.
- Локальная библиотека доступна offline. Максимум 20 именованных заготовок; имя trim/nonempty, одинаковые имена допустимы по ID. Save success появляется только после успешной записи. 21-я заготовка не вытесняет старые, quota может помешать раньше. Target не входит в заготовку.
- Отдельный demo toolbar: Live event, Control offline, Disconnect recipient, 20/20, Quota error, Corrupt storage, Evict source, Reset demo. Offline/quota/corruption переключаются повторным нажатием. Corrupt storage имитирует отказ чтения/записи без порчи пользовательского browser storage; реально повреждённое хранилище тоже обрабатывается. Reset demo требует подтверждения и сбрасывает данные только этого прототипа.
- Видимый keyboard focus, подписи полей, статусы текстом, literal HTML экранирован, направления не зависят от цвета. На 390px панели переходят в вертикальный поток; длинный raw текст имеет собственную прокрутку/визуальный перенос.

## Фактическая проверка

В локальном Chromium выполнены автоматизированные click/edit/send/load-сценарии для всех четырёх страниц. Проверены dirty cancel с сохранением выделения, неизменность target при загрузке, новая ручная запись, offline load, quota, 20/20, corruption, live while inspecting, сохранение scroll, eviction, clear, независимость подключений и переходы между концепциями. Горизонтального переполнения не обнаружено при 1920×1080, 1366×768 и 390×768. Просмотрены снимки композиций и узкой версии.

Дополнительно проверены system event с disabled copy, пустой payload, ручная отправка при OFF, trim/nonempty имени, совпадающие имена с уникальными ID, live во время ввода и открытого confirm/settings, ws:// URL validation, eviction по 1000 записям и 4 MiB, заглушка чрезмерного payload. Исправлены потеря фокуса при live и закрытие читаемой поверхности при перерисовке.

Сценарии и технические результаты сохранены в `.qa/`: `check.cjs`, `boundaries.cjs`, `edge-cases.cjs`, `results.txt`; снимки также там. Эти проверки подтверждают локальную браузерную симуляцию, не реальный транспорт или production-совместимость. Рендер внутри самого OpenDesign проверяется при открытии Preview пользователем; headless-проверка использовала тот же статический источник через локальный HTTP.

## Ограничения и принятые решения

Нейтральная тёмная палитра, serif-заголовки и моноширинный raw текст — выбранное для R1 направление, не согласованный бренд. Плотные метаданные используют меньший шрифт, чем основной текст. Изображения и внешние шрифты не требуются.

Реального backend и WebSocket-соединений нет. Shared backend memory представлена локальной симуляцией; `sessionStorage` удерживает историю и состояние при переходах в одном Preview, `localStorage` — заготовки. Это не обещает desktop persistence между запусками и не реализует общую backend-память между независимыми вкладками. Отказы browser storage показываются пользователю. Browser transport headers, binary, latency, request type, ACK и request-response корреляции не моделировались как backend-данные.
