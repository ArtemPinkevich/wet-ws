## 1. Goal and scope

Проверить общую техническую основу двух поставок до разработки посредника: ввод текста → реальный WebSocket → возврат без изменения. Одна исходная основа собирается в локальный Linux-контейнер с браузерным UI и Windows-программу с собственным окном и локальной логикой.

За границами: полный посредник и его независимый клиент-серверный стенд, внешнее/корпоративное размещение, другие ОС, коммерческий выпуск. Проверку с полностью отключённым внешним интернетом автор исключил 2026-10-05; автономность в этих условиях не подтверждена. Офлайн-сборка не требовалась.

## 5. Hidden requirements, decisions and constraints

PROP-01–04 первоначально были предложениями аналитика, DES-01–03 — инженерными решениями координатора по поручению автора. Отдельное предварительное согласие на каждый пункт не записано; итоговая поставка принята с указанными ограничениями.

- **PROP-01 / DES-02–03:** пустая строка, пробелы, переносы, Unicode и HTML-подобный текст сохраняются и выводятся буквально. Пустой ответ отличим от отсутствия ответа. Один текстовый message → один текстовый ответ, без JSON и нормализации; binary закрывается с 1003. Предел 0–65 536 байт UTF-8 включительно: UI при превышении сохраняет ввод, не отправляет и не обрезает; сервис при обходе UI закрывает с 1009. Проверки: 0/1/65 536/65 537 байт, многобайтовый текст и независимый клиент.
- **PROP-02 / DES-01:** подключение при открытии экрана; отправка после готовности. Tconnect = 5 000 мс от создания WebSocket, Treply = 5 000 мс после успешного send. До границы тайм-аут не наступает, при elapsed ≥ limit попытка завершается; реальный планировщик не обещает точного времени срабатывания. Отказ/зависание сохраняют ввод и допускают ручное подключение.
- **PROP-03:** одна попытка, прежний ответ очищается до отправки, ввод readonly и сохраняется. Несовпадение показывает реальный ответ и ошибку, завершает попытку; здоровое соединение можно использовать повторно.
- **PROP-04 / DES-03:** ошибка отправки, разрыв и тайм-аут возвращают управление и исключают старое соединение. Поздние события не меняют новую попытку; переподключение и отправка — разные ручные действия, автоматического повтора нет. Произвольные дубликаты в одном соединении не входят в контракт.
- **UX:** одна основная кнопка меняет действие подключения/отправки; Enter в поле вставляет перенос, данные доступны для чтения и копирования. Существенные переходы и пределы подтверждения — ниже.
- **Долговременное знание:** границы, поставки, изоляция renderer и протокол находятся в overview; выбор Electron позволил запускать тот же сервис в main без sidecar. Это кандидат rationale для ADR, не причина сохранять полный старый проект. ADR не создавался.

### UX impact — сведения исходного проектирования, не новые результаты

| Событие | Поведение / восстановление |
|---|---|
| Открытие / ручное переподключение | Подключение начинается автоматически, ввод разрешён, кнопка недоступна до исхода. Успех разрешает «Отправить», отказ/тайм-аут — «Подключиться снова»; само подключение текст не отправляет. |
| Отправка | Сначала валидация размера: превышение сохраняет ввод и прошлый ответ, попытка не начинается. Допустимый ввод фиксируется, старый ответ очищается, ввод readonly, повторный клик запрещён. |
| Ответ | Показать фактический текст, разблокировать ввод. Совпадение — «Ответ получен», несовпадение — ошибка без обязательного закрытия здорового соединения. Пустой ответ подписать вне тела «Ответ получен: пустая строка». |
| Ошибка send / разрыв / тайм-аут ответа | Завершить попытку и соединение, разблокировать ввод, ответ пуст, причина видна; восстановление вручную, без повтора отправки и влияния поздних событий. |
| Изменение ввода / закрытие после ответа | Сохранённый ответ пометить «Ответ предыдущей попытки», при несовпадении сохранить ошибку. Причина неудачи без ответа остаётся до новой отправки; подключение не стирает её. |

До первого обмена ввод и ответ пусты, подсказка «Отправьте текст, чтобы получить ответ». Tab: ввод → доступная кнопка → ответ; readonly доступен фокусу/копированию, disabled-кнопка пропускается. Enter/Space активируют кнопку в фокусе; события не переводят фокус на ответ. Цвет дополнен текстом, фокус заметен, статусы доступны средствам чтения экрана. Длинные строки переносятся без изменения данных, большие блоки прокручиваются; узкий экран сохраняет вертикальный порядок. Ввод живёт в открытом экране, сохранение после reload/закрытия не входит в объём.

**Verification expectations:** исходный UX предусматривал клавиатуру, фокус, чтение статусов, контраст, длинный текст, буквальный HTML, несовпадение, ошибку после успеха и ручное восстановление. Реально выполненное подтверждается только историческими отчётами в app/out/checks; полная доступность не заявляется.

**Происхождение критериев:** первоначальный SYS-04 включал обмен при недоступном внешнем интернете, без требования офлайн-сборки. Автор исключил эту проверку 2026-10-05; она не выполнена, автономная поставка остаётся направлением продукта. Бывший SYS-06 был действием приёмки автора, а не функцией системы. Версии и артефакты зафиксированы в исторических отчётах app/out/checks; старые указания «закрепить перед первой сборкой» и «ещё реализовать диагностику» утратили рабочую актуальность.

Методические источники исходных документов: [NASA — проверяемость требований](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/), [W3C — подписи](https://www.w3.org/WAI/tutorials/forms/labels/), [W3C — обратная связь](https://www.w3.org/WAI/tutorials/forms/notifications/), историческая дата проверки 2026-10-03. При миграции повторно не проверялись; соответствие стандартам не заявлено.
