## Границы / System Context

Используй при изменении участников, внешних систем или ответственности продукта. Покажи человека, систему как целое, действительно внешние системы и смысл связей. Браузер, desktop-оболочка и внутренняя логика не становятся внешними системами ради детализации. Поставки — способы эксплуатации одной системы. Отделяй текущий echo-пример от предложенного посредника и его независимых клиента/сервера.

Не добавляй технологии, внутренние компоненты и развёртывание в Context. Короткая Mermaid-схема нужна только если проясняет вопрос; без самостоятельной ценности достаточно текстовых границ в пакете.

## Container / технический подход / размещение

Используй при вопросе о процессах, владельцах состояния, внутренних протоколах, выборе технологии или отличиях поставок. Покажи только затронутые выполняемые приложения, ответственность, технологии и связи; библиотека не отдельное приложение, Docker container не C4 Container. Deployment дополняет представление, не является следующим обязательным уровнем.

При первом выборе сравни подходы по реальным ограничениям, предпочтениям автора, общей исходной основе, упаковке и проверяемости. При доработке сравни только варианты нерешённого вопроса. Для затронутой поставки объясни путь реального WebSocket, владение локальной логикой и процессы запуска; не повторяй обе поставки, если вопрос касается одной.

Отделяй документированную возможность от собственной сборки, общий исходный снимок от сходства экранов, сборку от запуска и транспортного обмена. Windows не доказывает другие ОС, локальный контейнер — внешнее размещение. Для внешних технических фактов проверяй первичные источники и фиксируй дату.

При конкретном изменении границы сопоставь владельца состояния/контракта и направления зависимостей до/после; проверь конфликт ownership с инвариантами на реальном сценарии. Сравни решение внутри существующей структуры с новой границей: какое текущее сцепление или смешение ответственности она устраняет и кто её использует. Малый wrapper допустим для защиты инварианта/зависимости; отсутствие слоя само по себе не проблема. Это метод ограниченного анализа, не обязательная полная архитектурная стадия.

Component/Code, ADR и дополнительные документы нужны только для самостоятельного вопроса. Отмечай предложения, принятые решения и проверенные результаты раздельно; новое поведение возвращай в Context Pack, полномочия на анализ не разрешают реализацию. Нереализованная дельта не становится текущим overview.
