# Iteration Context Pack

Создавай один `docs/engineering/iterations/iteration-NN/context-pack.md`. Выбирай нужные поля; не оставляй пустой каркас ради шаблона. Порядок работы задаёт [orchestrator](../SKILL.md).

## Состояние и scope

Укажи дату, статус, цель, выбранные user stories (ID и ссылки), границы и исключения. Приведи только необходимые текущие источники. Для каждой истории зафиксируй наблюдаемое поведение, критерий приёмки и статус.

## Требования и решения

Context Pack хранит change-context, не копию canonical architecture. Разделяй исходные данные, выводы, предложения, принятие, реализацию и проверку. Укажи источник и дату существенного согласования. Открытый блокирующий вопрос содержит владельца решения и влияние на готовность. Отсрочку фиксируй только при реальном риске: причина и условие возврата, подробности — в соответствующем backlog.

Выявляй существенные скрытые требования без числового лимита: каждое связывай с поведением и проверкой. По применимости проверь границы данных, ошибки, восстановление, порядок событий, конкуренцию, повторы, устаревшие результаты, очистку, очереди и завершение ресурсов. Не добавляй нерелевантные категории ради полноты.

## Gates

Для выполненного gate запиши `PASS / SKIP / BLOCK / ESCALATE`, основание и следующий шаг при необходимости. Impact (`NO_CHANGE / DELTA / REVIEW`) не заменяет готовность. PASS относится ко всему существенному объёму gate: принятие картинки не закрывает открытые UX-решения.

| Hidden Requirements | | |

| UX Impact | | |
| Reliability & Concurrency | | |

Заполняй по мере прохождения. `NOT RUN` означает отсутствие проверки, не успешный SKIP. В ретроспективе используй `UNKNOWN / NOT RECORDED`, если исторических доказательств нет; последующее завершение не доказывает прежний Ready PASS. Код начинается только после Implementation Ready PASS.

## Нужные дельты

- Architecture impact и краткая delta: изменяемые ответственность/owner, зависимости и основание; ссылка на нужную часть canonical overview. Текущее устройство остаётся в `docs/engineering/architecture/overview.md`; не копируй его и не создавай полную архитектуру итерации. Принятое, но не реализованное не становится текущей архитектурой.
- Protocol impact и краткая delta: затронутые protocol units/owner, ссылки на единственные определения, изменение поведения и существенные ограничения. Свяжи обе дельты с критериями и проверками; при отсутствии изменения достаточно SKIP с основанием. Не добавляй обязательных пустых New owners/New layers/New responsibilities.
- UX: поведение и состояния; для визуального изменения — только затронутые файлы `iteration-NN/mockups/`, зеркалящие canonical `docs/engineering/ui/mockups/`. Укажи статус каждого файла и согласованные удаления. SKIP/NO_CHANGE не создаёт макетов.
- Дополнительный артефакт создаётся только при самостоятельной ценности.

## Передача и реализация

При ESCALATE сформулируй один трудный вопрос, причину передачи Astra, решение, отклонённые варианты и последствия. Принятое решение верни сюда. Для фактической передачи используй [handoff](iteration-handoff.md); новая сессия сама по себе не требует файла или повторной передачи.

После Ready PASS укажи необходимые шаги реализации и их результат. Не дублируй состояние отдельным постоянным handoff.

## Проверка

В существующей Verification зафиксируй команду и результат полного `npm run check` из app перед завершением change set, включая документационные изменения. Во время работы допустимы исправляющие и узкие проверки, но они не заменяют этот финальный check; порядок задаёт [orchestrator](../SKILL.md#workflow). Не копируй настройки tooling и не создавай отдельный code-quality раздел/отчёт. Тесты остаются самостоятельным слоем проверки по изменению.

Свяжи критерии и существенные риски с ожидаемым и фактическим результатом, командой/наблюдением и доказательством. Разделяй unit-проверки, сборку, запуск, транспорт и проверку готового артефакта. Укажи регрессии и ограничения; не выдумывай выполненные проверки.

## Independent Reviewer — до Done

Временный контекст собирается по [reviewer context contract](../SKILL.md#reviewer-context) из существующих артефактов. Зафиксируй существенные findings, исправления, релевантную повторную проверку и ограничения доказательств. Verdict reviewer не заменяет статусы gates, отсутствие review не является PASS; отдельный отчёт/handoff не нужен.

## Iteration Done

Проверь выполнение stories и скрытых требований, Verification и применимую Conformance без блокеров, reviewer pass и закрытие существенных замечаний, актуальность canonical, приёмку и известные ограничения.

Принятая, реализованная и проверенная UI delta обновляет canonical; затем проверяются ссылки и очищается delta. Перед потерей уникального материала проверь, что именно это содержимое сохранено в достижимом Git-коммите. Если истории нет — сохрани материал до решения автора; не делай автоматический коммит и не заявляй завершённую очистку. Устаревшие непринятые варианты явно исключи из активной delta.

Дополнительные действия при завершении выполняй по локальному расширению инструкций, если оно есть. Результаты локальных действий сохраняй там, где это расширение указывает; публичный Context Pack хранит технический результат и доказательства.

## Process Health Check — после Done

Один неблокирующий проход по [правилам orchestrator](../SKILL.md#process-health-check): избыточная сложность, выбор модели, gates/skills и существенные вмешательства автора. Отделяй факты, вероятные причины и неизвестное. Вмешательства классифицируй как CONTENT_ONLY / PROCESS_TUNE / SYSTEMIC_ISSUE с источником и последствиями.

Результат NO_CHANGE / TUNE / ESCALATE содержит краткие основания и ограничения доказательств. Это рекомендации; менять процесс можно только после явного решения автора. Не переоткрывай Done, не создавай отдельный отчёт и не придумывай ретроспективный проход.
